# 上传即分析与分层可视化

2026-11-23。针对“图上已有的信息还要手工填写”“复权不一致导致整个图表空白”的交互修正。

## 现在怎么用

打开 <http://127.0.0.1:4173/#chart-reports>，保留默认勾选的“自动识别图中信息”，选择图片后直接点击“上传并生成报告”。没有配置模型时先保存截图，仍沿用原配置、累计预算和显式开始规则。

代码、日期、周期和复权在同一次识图请求中提取，不额外增加一次识图调用；识别结束后展示识别信息，并带入可选的手动补充面板。默认不需要填写代码、日期，也不需要逐项勾选“与截图一致”。只有主动展开手动面板时才切换到原手动模式。

已保存的旧报告刷新后也适用新的可视化展示，不重新调用模型、不重新取行情。

## 按已有证据直接展示

| 当前资料 | 展示方式 |
| --- | --- |
| 同一证券和周期能核对，行情归档完整，复权等核对通过 | 完整历史 K 线、均线、未来分类区域与原有条件参考线 |
| 同一证券和周期能核对，但日期或复权未完全对齐 | 展示明确标记的“同一证券不复权行情背景”，说明与截图可能口径不同；隐藏精确买卖参考，不把背景规则当作截图已确认的结论 |
| 分时图、缺日期、周期无法确认或行情不可用 | 展示基于图像观察的三种条件情景分支图、触发/失效条件及图中证据；不补造价格轴、OHLC 或交易日期 |
| 图片无法辨认或非走势图 | 提示换图，不绘制没有依据的行情 |

背景图继续使用已有 ATR 分类边界，仅表示涨跌幅如何分类。图像分支图只表达条件关系。二者都不宣称确定价格路径、胜率或预测效果。

数据完整性冲突、证券不同、周期不同等情形不会混用行情。此时图像情景仍可呈现，并说明行情背景不可用。

## 实现和兼容

- 新增 POST `/api/chart-uploads`，仅需 `image_base64`，可选 `question`；沿用本机 `RESEARCH` 模式、幂等键、大小限制和唯一 worker。
- 原始上传请求保留不变，识别后的分析参数单独保存为 `resolved_request`，附 `metadata_notes`。没有把模型识别伪装成人工确认。
- 自动模式先进行一次已有预算预留与识图调用，再由确定性规则校验提取字段，资料足够时运行行情算法。分时图不会被默认成60分钟，缺少日期不会用当天替代。
- 自动识别与手动输入沿用同一严格字段验证。上传内部占位值不是图像事实，不对用户展示为日期或代码，也不会据其查询证券行情。
- GET `/api/chart-analyses/{id}/visualization?preview=true` 增加渐进展示：响应携带 `view_mode=BACKGROUND` 及具体 `warnings`，且不携带精确买卖参考线。旧版严格接口默认行为保留。
- 前端仍验证图表、报告快照和行情摘要，图像情景与行情背景分别标明来源；下载自动报告时也使用识别后的信息，缺失字段明确标记未知。
- 超时/崩溃的付费调用仍登记 UNKNOWN，保留预留，不自动重发。没有新增后台抓取、重置预算、交易或通知权限。

## 验证

保留全部原断言和 Windows DPAPI 覆盖。新增验证包括：只上传图片即可提交、同一幂等请求不重复生成、一次识图后才运行算法、保留原始请求、缺日期/周期不猜测、分时图降级为图像情景、前复权背景无买卖参考、错证券拒绝行情混用，以及 UNKNOWN 不重发。

本机完整检查通过：447 项 Platform、58 项前端测试、类型与静态检查、生产构建、25 条合成契约、7 个进程中断点和100次同幂等键提交。浏览器核对了默认简化表单，以及原来被阻断的K线报告现在可显示背景图、原分时报告可显示情景图；这些读取没有新增真实模型调用。识图准确率与预测效果仍未通过独立真实样本验证。
